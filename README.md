# GophKeeper

**GophKeeper** — это приложение для безопасного хранения конфиденциальных данных (паролей (с поддержкой OTP), текстовых заметок, банковских карт и приватных файлов). 

Проект написан на Go. Сервер поддерживает работу как по HTTPS, так и по gRPC, использует TLS-шифрование и документирован с помощью Swagger. Клиент представляет собой интерактивное терминальное приложение (TUI), построенное на базе фреймворка **Bubble Tea**.

Взаимодействие компонентов построено по клиент-серверной архитектуре с механизмом Server-Sent Events (SSE) для мгновенного оповещения других устройств пользователя о необходимости синхронизации.

## 1. Требования к окружению

Перед началом работы убедитесь, что в вашей системе установлены следующие инструменты:

* **Go** — версия 1.21 или выше.
* **Make** — утилита для автоматизации задач.
* **Protocol Buffers v3 (`protoc`)** — компилятор Protobuf для gRPC.
* **Swag** — утилита для генерации документации Swagger из аннотаций в Go.

---

## 2. Подготовка к использованию

Перед первой сборкой проекта необходимо сгенерировать TLS-сертификаты, Protobuf-файлы и моки для тестов. Для этого выполните команду:

```bash
make generate
```

---

## 3. Сборка проекта

В проекте настроено динамическое вшивание версии, даты и коммита из Git в бинарные файлы. Все собранные файлы сохраняются в директорию `./bin/`.

* **Стандартная сборка** (сервер и клиент под текущую операционную систему):
  ```bash
  make build
  ```
* **Полная кросс-компиляция клиента** (сервер под текущую ОС + клиент под Windows, Linux и macOS Intel/Apple Silicon):
  ```bash
  make build-all
  ```
* **Очистка файлов сборки:**
  ```bash
  make clean
  ```

## 6. Документация API (Swagger) и тестирование SSE / REST

В проекте настроена автоматическая генерация спецификации Swagger. Все эндпоинты блока `api` защищены авторизацией по JWT-токену и требуют обязательной передачи идентификатора клиентского устройства.

### 6.1 Swagger 

1. **Запустите сервер приложений в режиме HTTPS:**
   ```bash
   ./bin/server -t=<ваш_ключ_jwt>
   ```

2. **Перейдите в браузере по ссылке:** [https://localhost:8080/api-docs](https://localhost:8080/api-docs)

3. **Процесс регистрации в Swagger:**
   * Выполните POST-запрос `/user/register`.
   * Скопируйте полученный в ответе JWT-токен.
   * Нажмите кнопку **Authorize** в правом верхнем углу страницы.
   * В поле ввода вставьте токен в формате: `Bearer <ваш_jwt_токен>`.


### 6.2 Тестирование Server-Sent Events

Эндпоинт `/api/event` отвечает за передачу событий синхронизации клиенту. При успешном вызове `Push` на одном устройстве сервер отправляет сообщение `sync` всем остальным подключенным устройствам текущего пользователя.

Для проверки работы механизма выполните следующие шаги:

1. **Выполните шаги из пункта 6.1.**
2. **Имитируйте подписчика в терминале:**
   * Откройте окно консоли и выполните указанную ниже команду для подписки на события сервера.
   * В заголовке команды укажите скопированный токен.

```bash
curl -k --no-buffer -N -X GET https://localhost:8080/api/event \
  -H "Authorization: Bearer <ваш_jwt_токен>" \
  -H "device-id: device-1"
```
*Терминал перейдет в режим ожидания и останется открытым.*

3. **Выполните push-запрос через Swagger**, чтобы сымитировать отправку изменений с другого устройства:
   * Выполните POST-запрос `POST /api/push`, указав в поле заголовка `device-id` идентификатор второго устройства (например, `device-2`).

После этого в терминале (где запущен `curl`) появится сообщение в формате:
```text
data: sync
```

## 7. Спецификация API

Сервер поддерживает следующие HTTP-эндпоинты:

### 7.1 Управление пользователями

| Метод | Эндпоинт | Аутентификация | Заголовки | Описание |
| :--- | :--- | :---: | :--- | :--- |
| `POST` | `/user/register` | Нет | `Content-Type: application/json` | Регистрация нового пользователя. Возвращает JWT-токен. |
| `POST` | `/user/login` | Нет | `Content-Type: application/json` | Аутентификация пользователя. Возвращает JWT-токен и соль. |
| `GET` | `/user/salt` | Нет | *отсутствуют* | Получение соли пользователя для безопасного хеширования на клиенте. |

### 7.2 Синхронизация и работа с данными

| Метод | Эндпоинт | Аутентификация | Заголовки | Описание |
| :--- | :--- | :---: | :--- | :--- |
| `GET` | `/api/event` | JWT | `device-id` | Поток событий (SSE). Отправляет `sync`, если данные изменились. |
| `POST` | `/api/pull` | JWT | `device-id`, `Content-Type: application/json` | Запрос обновленных секретов (сжатие Gzip). |
| `POST` | `/api/push` | JWT | `device-id`, `Content-Type: application/json` | Отправка локального журнала изменений (сжатие Gzip). |
